Scan v1.0.1 fixes memory recovery and column resizing.

- **Automatic memory recovery:** retry memory-heavy queries with one thread, then raise the memory limit when needed. Growth is capped at 4 GB or one eighth of the Mac's RAM, whichever is smaller, while respecting a higher initial setting. An increased limit is shown in the status bar.
- **Keep rows loading after failed sorts:** restore the previous view so subsequent pages remain usable instead of stopping after cached rows.
- **Column resizing:** header dividers show a horizontal resize cursor; drag to adjust the width, including after horizontal scrolling.
- Updated settings text and removed the plan-budget column from the README benchmarks.

## Requirements and installation

Apple Silicon Mac (M1 or later), macOS 14 or later. Ask additionally requires macOS 26 or later with Apple Intelligence available.

Download **Scan-v1.0.1-macos-arm64.dmg**, open it, and drag **Scan.app** to **Applications**. Quit an existing Scan instance before replacing it. The ZIP is an alternative and includes the optional `bin/scan` CLI.

The app is ad hoc signed, **not Developer ID signed or notarized**. If macOS blocks the first launch, try opening Scan, then choose **System Settings → Privacy & Security → Open Anyway** and confirm. [Apple's instructions](https://support.apple.com/en-us/102445).

Checksums are in **SHA256SUMS.txt**. With both archives in the download directory, run `shasum -a 256 -c SHA256SUMS.txt`.

## Validation

All 27 tests passed, including the reported memory failure reproduced by sorting the 3.7 GiB million-row Parquet fixture, fetching sorted pages beyond row 768, bounded memory growth, view recovery after failed sorts, and column drag behavior after horizontal scrolling. Release bundle versions, signatures, archive integrity, and extracted ZIP/DMG contents were verified.
